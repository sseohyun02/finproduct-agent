# 금융상품 Agent — 그래프 설계 확정 사항

## 배경
- 대회 핵심: 온톨로지 + 그래프DB + 관계(멀티홉) 활용 필수
- 기술: TTL(RDF/Turtle) — PPT 방법론 채택
- 데이터: 원본 4종(채권·국내ETF·해외ETF·펀드) + 외부수집(ETF 구성종목)

## 핵심 원칙
- **SQL로 되는 건 속성, 관계 타야 하는 건 노드** (사용자 확립 기준)
- 단순 필터(위험등급·보수·지역)는 SQL, 관계 순회(구성종목·발행사그룹)는 그래프
- 임의 판단 최소화: 명백한 것만, 애매하면 원본/보류

## 노드 (5종)
| 노드 | 설명 | 출처 |
|---|---|---|
| Product(상품) | ETF/ETN/Fund/Bond | 원본 4종 |
| Company(회사) | 발행사+구성종목 통합 | 채권 발행사 + ETF 구성종목 |
| AssetManager(운용사) | 운용사/증권사 | cu_fund_mgmt_co |
| Group(금융그룹) | 발행사 상위 그룹 | 발행사명에서 추출 |
| Theme(테마) | 반도체·2차전지·AI 등 | 상품명에서 추출 |

## 속성 (SQL로 처리, 노드 아님)
- 공통: 위험등급, 순자산, 투자지역, 자산군
- ETF: 총보수
- 채권: 만기, 표면금리, 듀레이션, 신용등급, 채권분류

## 관계 (5종)
| 관계 | 방향 | 비고 |
|---|---|---|
| holds(보유) | 상품→회사 | 비중 값 포함, ETF 구성종목 |
| issuedBy(발행) | 채권→회사 | |
| belongsToGroup(소속) | 회사→그룹 | 주요 금융그룹만 |
| managedBy(운용) | 상품→운용사 | |
| hasTheme(테마) | 상품→테마 | |

## 통합 방식 결정
- **회사 노드 통합**: 삼성전자(구성종목) = 삼성전자(발행사) → 하나의 노드
- 효과: "삼성전자 주식 담은 ETF와 삼성전자 발행 채권"을 한 번에 연결

## 제외/보류 결정
- **기초지수 노드 제외**: 89% 비어있음 + 구성종목 직접 수집으로 대체됨
- **섹터 제외**: 변별력 없음(pd_sect_cd 대부분 동일값)
- **금융그룹**: 주요 그룹만(신한·현대차·KB·하나·삼성·우리·NH·IBK·롯데·BNK·메리츠·미래에셋·키움·한국투자·JB·DGB)
  - 지자체·독립계캐피탈·일반기업은 그룹 없이 발행사로만

## 데이터 수집 현황
- **ETF 구성종목**: pykrx로 국내ETF 1,132/1,202개(94%) 수집 완료 (data/raw/etf_portfolio.xlsx)
  - KRX_ID/KRX_PW 로그인 필요(.env), 종목코드·종목명·비중 포함
  - 현금·선물·설정현금액 등 비종목 항목 섞여있음 → 그래프 넣을 때 필터
  - 해외ETF·ETN·펀드는 구성종목 없음(pykrx 국내 전용)
- **그룹 매핑**: 발행사명 이름 기반, 주요 금융그룹 약 48% 커버(2만/4.2만)
  - 나머지는 그룹 없음(의미 없는 것들이라 OK)

## 멀티홉 활용 예시 (그래프가 필요한 질문)
- "삼성전자 담은 ETF의 운용사" (회사→상품→운용사)
- "신한금융그룹 채권" (그룹→회사→채권)
- "반도체 ETF들 공통 보유 종목" (테마→상품들→회사 교집합)
- "삼성전자 주식 담은 ETF와 삼성전자 발행 채권" (회사 양방향)

## 남은 작업
1. 회사 노드 정제: 구성종목명 ↔ 발행사명 매칭(통합 위해, 표기 통일)
2. 보유비중 TTL 표현 방식 결정 (RDF reification 등)
3. 그룹 매핑 완성 (이름 규칙 + 지자체 묶기 + 소수 수동)
4. 테마 추출 정제 (오염 키워드 제거, 명확한 것만)
5. 실제 그래프 구축 (TTL 인스턴스 생성)
6. query_builder (concepts.json 런타임 식별 → SQL/그래프 쿼리)
7. HyperCLOVA X 연동 (의도추출 + 답변생성)
8. FastAPI GET /answer 엔드포인트
